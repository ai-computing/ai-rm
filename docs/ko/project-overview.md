# 프로젝트 개요

[문서 홈](README.md) · [English](../project-overview.md)

## 해결하려는 문제

GPU·NPU·CPU가 섞인 AI 인프라는 실행 백엔드, 메모리 계층, 소프트웨어 인터페이스가 서로 다릅니다. 장치를 나열하는 것만으로는 작업을 어디서 실행하고, 상태를 어떻게 옮기며, 다른 구성과 어떤 기준으로 비교할지 설명하기 어렵습니다.

AI-RM은 이를 **장치 탐지 → 데이터 이동 → 워크로드 실행 → 클러스터 통합 → 관측·측정**의 다섯 책임으로 나눕니다. 대상은 GPU, FuriosaAI RNGD, Rebellions ATOM, CPU, GB10이며 기본 클러스터 환경은 Kubernetes + llm-d입니다.

추론 엔진은 **aicomp의 Optimus Prime**으로 통합하고 FASOP을 내부 계획·탐색 요소로 포함하는 방향입니다. AI-RM은 자원·클러스터·증빙의 상위 통합을 맡습니다. 기존 추론 소스 저장소는 이전 중 유지하며 이번 작업은 문서·계획 설정만 변경합니다. [엔진 통합 설계](engine-integration.md)를 참고하세요.

## 이 저장소가 관리하는 것

| 산출물 | 목적 |
|---|---|
| 계층형 아키텍처 | 기술별 책임과 연결 지점을 정의 |
| 인터페이스 가이드·작업 카드 | 각 구현을 rm-core 공통 계약에 연결 |
| 서브모듈 커밋 | 특정 통합 버전의 정확한 구성요소 조합 기록 |
| CLI·Make 명령 | 선언된 설치·테스트·매니페스트 배포 실행 |
| 공개 문서·그림 | 실제 클러스터 없이도 과제 구조를 이해 |
| 성과지표 대응표 | 연구 영역을 측정 정의와 증빙 위치에 연결 |

커널·모델 실행·전송 구현·운영 UI는 각 구성요소 저장소에서 관리합니다. 접근 상태는 [현재 상태](status.md)를 참고하세요. `duet`은 비공개 선택 구성요소입니다.

## 연구 질문

1. 이종 작업 배치에 필요한 능력을 공통 장치 모델로 표현할 수 있는가?
2. KV 전송, 전문가 오프로딩, 통합메모리 검색에 어떤 데이터 경로가 적합한가?
3. Prefill·decode·학습을 클러스터 실행 환경에 어떻게 연결하는가?
4. 지연·처리량·전력·SLO를 비교 가능하고 재현 가능하게 기록하는가?

![가속기 보드·CPU 메인보드·소형 컴퓨팅 시스템의 개념 이미지](../assets/hardware-workbench.png)
*AI로 생성한 일반 하드웨어 이미지입니다. 실제 장비 식별 자료나 과제 구축 증빙이 아닙니다.*

GPU는 참조·이종 실행 백엔드, RNGD는 NPU 실행·prefill·offload·학습 연구, ATOM은 decode·이종 KV 전송 연구, CPU/DRAM은 호스트 연산·staging, GB10은 비공개 `duet`의 CPU–GPU 협업 검색 연구와 연결됩니다. 실제 지원 조합은 구성요소 문서에서 확인하세요.
